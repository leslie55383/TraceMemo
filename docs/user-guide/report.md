# 生成群聊日报和总结

如果你每天在多个群里聊天，晚上不想重新翻几十个群，可以让 TraceMemo 根据一个群的聊天内容整理出一份可阅读、可保存的报告。

## 报告适合做什么

典型场景包括：

- 整理今日工作群的讨论重点；
- 回顾昨日错过的决定和资源；
- 汇总近 7 天的项目进展、待办和未解决问题；
- 把群里的图片、语音统计和重要消息放进一张长图或 HTML 页面。

## 生成步骤

你可以从两个入口开始：打开一级导航“日报”后新建报告，或者在“档案”中选中一个群聊并点击“生成 AI 日报”。

1. 选择一个群聊。当前日报入口只支持群聊，不支持单聊。
2. 选择时间范围：今日、昨日、近 7 天、本周、本月，或填写自定义起止时间。本周从本地周一零点起，本月从一日零点起，均截至当前时间；自定义结束时间不得早于开始时间。
3. 按需要选择参与总结的消息类型，先从文字开始最容易核对。
4. 选择报告模板/内容模式并开始生成。
5. 等待“整理输入 → AI 生成 → HTML/PNG 导出”完成。

报告可能包含主题、重要消息、问答、资源、待办、未解决事项、关键词、活跃统计，以及可用媒体的精选内容。具体展示内容会随消息类型、资源可用性和模型能力变化。

## 如何检查报告

### 调整日报图片识别

在日报生成页的“日报图片识别”中，可以设置“单份日报最多识别图片数”：默认 3 张，可设为 0–20 张，设为 0 可关闭图片识别。手动设置会保存在当前客户端，同时保存为定时和 Agent 日报的默认配置。

默认只选择有讨论互动的热点图片。勾选“热点图片不足时补入普通图片”后，热点图片仍优先，剩余名额可用于没有回复的截图、公告图等。重复图片按同一张计数，无法在本机读取的图片仍可能识别失败。图片数量是上限，不保证每次都有足够的可用图片。

图片处理方式有三种：视觉模型理解图片；仅本地 OCR 提取文字；本地 OCR 优先，无结果时调用视觉模型。仅 OCR 模式不会把原图发给视觉模型，但提取的文字仍会交给当前文字模型总结；文字模型为远程服务时，这些文字会外发。OCR 不会推断人物、场景或图表含义。

“图片预览与选择”只读取本机图片，不调用 AI；每页读取 24 条，最多同时读取 3 条。预览后可以勾选要识别的图片消息，包括普通图片，或恢复自动选图。手动勾选最多为当前识别上限条数，重复图片仍会合并；换群、改时间范围、数量、选图规则或消息类型后，手动选择会重置。

图片读取或识别失败时，可以“仅重试失败图片”，成功结果保留；也可明确选择继续文字总结或停止。后台定时/Agent 日报无法等待交互，遇到图片处理失败会停止本次生成并记录原因，不会继续发送不完整报告。

提高视觉识别上限会增加模型用量和等待时间。在“自动化 → 定时日报”中，可开启“为此规则单独设置日报”，保存该规则自己的图片数、处理方式、模块、密度以及文字/视觉模型；未单独配置时，沿用手动日报保存的默认设置。旧规则的发送目标和启停状态保持原样。

输入整理完成后，右侧任务状态会显示图片消息条数、本次选中的图片数，以及未达热点条件、重复图片合并、缺少标识或资源、超过数量上限的数量。读取或模型识别失败另列在“图片识别”详情中，不会混成筛选跳过。关闭图片识别时也会明确提示。

同一张图片的识别内容可在 10 分钟内复用，但日报中的发送者、时间和来源消息始终对应本次选中的聊天记录。

### 配置内容与密度

“日报内容与密度”支持简洁、标准、详细三档，影响提示词、候选条数和摘要长度。勾选需要展示的话题、重要消息、待办、问答、资源、统计或媒体模块；未勾选模块在报告数据中清空，并关闭展示标记，供内置和社区模板一致使用。概要始终保留。密度与模块选择会在本机记住。

“本周”“本月”表示当前自然周/月的阶段总结，不是已经结束的完整周/月；要整理上一周或上个月，使用自定义起止时间。定时规则仍按每日时间触发，范围可选本周或本月；本轮未加入按周/月触发的调度器。

### 长记录自动分段

周报、月报或较活跃群聊的文字输入过长时，会自动按记录顺序拆段提取证据，再跨段合并成最终报告；不需要另开开关。单条长消息也会拆分并重复标明原始编号、日期和发送者，不会为了满足输入长度而直接截掉尾部。消息数量、活跃人数和媒体统计仍以本机读取的全量记录计算。

右侧会显示“长记录分段总结”“长记录合并”和最终生成进度。分段会增加模型调用与等待时间，全部文字模型步骤共用本次日报的超时预算；图片识别、语音转写和导出仍各有原来的处理超时。输入超出分段上限、模型输出过长或被截断、某段失败时会明确停止，不会跳过失败段后导出。

手动日报在模型步骤失败后，可用同一模型重试，复用本次任务内已成功整理的分段；切换模型会重新整理。分段缓存只留在当前进程内，关闭、重置任务或重启后不保证保留；后台规则重新执行时会重新整理。用量包含成功分段、合并及最终生成，未返回计数时为估算，不能作为账单。

报告会注明分段处理，压缩可能省略细节，重要结论仍需核对原消息。字符预算只是保守的应用限制，不保证适配每种模型的上下文；仍提示上下文不足时，请缩小范围或选择更合适的模型。定时、Agent 日报共用同一分段流程。

### 核对报告内容

报告中的重点结论会关联来源消息。对于重要决定、金额、时间和责任人，打开对应原消息核对，不要把 AI 生成的摘要当成新的事实来源。

图片无法读取时，报告可能只保留消息类型和上下文；模型未通过图片理解验证时，图片精选会被跳过。语音在日报中可参与数量和活跃度统计，但不要把统计当成语音内容已经被完整转写。

## 保存、查看和删除

生成成功后会保存本地 HTML 与 PNG，并出现在日报历史中。你可以复制图片、打开文件位置或重新生成。删除历史日报只删除本地生成的报告文件，不会影响微信聊天数据库。

## 定时日报（在自动化里）

定时日报现在是「自动化」里的一种规则，不再单独占一个页面：打开一级导航的「自动化」，新建或编辑一条「定时日报」规则，选择群聊、执行时间、日报范围、消息类型和发送目标。日报页顶部的指引条也会直接跳到自动化。

TraceMemo 会按计划执行：

```text
定时触发 → 读取群聊 → 生成报告 → 保存 Report History → 尝试发送
```

生成和发送是两个阶段。当前微信发送能力不可用、未绑定或发送失败时，报告仍会保存，PNG 和执行记录也会保留；这类结果会显示为“已生成，但未发送”或“已生成，发送失败”。

执行记录支持查看已生成的日报。对“等待发送”或“发送失败”的记录，可以直接重试发送，重试会复用已经生成的 PNG，不会重新调用 AI 生成整份报告；完整执行状态和发送边界见[如何把聊天变成可用的信息](../concepts/how-it-works.md#动作执行与审计)。

发送目标当前支持**当前群聊、文件传输助手、自己、指定好友**——还不是任意群发。

## 让报告更可靠

- 先选正确的群和时间范围；
- 不确定时先只选择文字消息；
- 群太活跃时分成“今日”和“近 7 天”两次生成；
- 看到待办和结论后回到原消息核对上下文；
- AI Provider 不可用时先检查模型配置和网络/本地服务状态。
